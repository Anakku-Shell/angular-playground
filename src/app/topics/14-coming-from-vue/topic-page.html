Angular for Vue 3 developers (Composition API, <script setup>). Every card puts a Vue example next to its Angular twin, with a live demo. The first four cards map what you already know; the last three follow one CRUD flow from the form to the server and back. The code lives in src/app/topics/14-coming-from-vue/.

Most Vue ideas have a direct Angular twin with another name. The four that change the most:

  • Signals are called. ref becomes signal, and you read it with count() instead of count.value. You write it with set / update, and a change is detected only when the value is a new one: push into an array and nothing updates.
  • Services instead of composables and Pinia. A class that dependency injection creates and gives to whoever calls inject().
  • Forms and HTTP are built in. Reactive Forms replace VeeValidate, HttpClient replaces axios.
  • HTTP returns Observables, not Promises. Nothing is sent until you subscribe(), and the response arrives in a callback.

The three CRUD cards follow one request through the app:

 form (fields + validators)                       card CRUD: Form
   │  submit(): valid? → build a ContactDraft
   ▼
 ContactsApi.create(draft)  →  HttpClient.post    card CRUD: Request
   │  interceptors → POST https://dummyjson.com/users/add
   ▼
 subscribe({ next, error })                       card CRUD: Response
   next:  add to the list, clear the form
   error: show a message, keep the form

The CRUD cards use DummyJSON, a public fake API: it needs a network connection, and it answers every write as if it saved it, but stores nothing.

A component: ref, computed, watchEffect → signal, computed, effect

In short

An Angular component is a class with a @Component decorator that holds its selector (the tag name), its template and its styles. State is a signal, the equivalent of ref, and derived values are computed, as in Vue.

Vue → Angular

  • The forgotten () is the #1 mistake: {{ count }} prints the signal function, not its value. Write count(), in the template and in the class.
  • effect is for side effects (storage, logs, a non-Angular library). To derive a value, use computed. There is no watch(source, (new, old) => …): read Signals for the alternatives.
  • The CLI generates components: ng g c contact-list creates the class, template, styles and spec in one folder.

Templates: :prop, @click, v-model, v-if, v-for

In short

: becomes [ ], @ becomes ( ), v-model becomes [( )], and v-if / v-for become the built-in blocks @if / @for. Interpolation is the same {{}}.

Vue → Angular

  • track is mandatory in @for: it is Vue's :key. Use a stable id, never the index for lists that change.
  • Templates are type-checked: a typo in a property name fails the build, like in a .ts file.
  • Older code uses *ngIf and *ngFor, the previous syntax: see Control flow.

Props, emits, v-model, slots → input, output, model, ng-content

In short

The child declares input() for props, output() for events and model() for a two-way value. The parent binds them with [max], (limit) and [(value)], and anything between the child's tags is projected into its <ng-content />.

Vue → Angular

  • Inputs are read-only signals in the child: this.max(). Only a model() can be written from inside.
  • Projected content belongs to the parent: its bindings use the parent's signals, as in Vue.
  • More patterns (aliases, transforms, queries): see Component communication.

Pinia and composables → services and inject()

In short

A service is a class marked @Injectable. With providedIn: 'root' there is one instance for the whole app, so it works like a Pinia store: state in signals, getters as computed, actions as methods. Components get it with inject(FavoritesStore).

Vue → Angular

  • Where it is provided decides how many instances exist: root for one per app, a component's providers: [] for one per component (and its children).
  • Services hold more than state: API calls (the next cards), logging, anything a component should not do itself. That keeps components small.
  • For bigger apps there is NgRx SignalStore, the closest thing to Pinia: see State management and Dependency injection.

CRUD 1 · The form: fields and validation

In short

The contacts app above is this card's demo. Start with the form on its left.

The form model lives in the class: each field has an initial value and its validators. The template binds each input with formControlName and reads the state of a field (touched, invalid, hasError()) to show messages. On submit, an invalid form only marks every field as touched, so all its errors show.

Vue → Angular

  • NonNullableFormBuilder: reset() goes back to the initial values instead of null, and the value types stay string, not string | null.
  • form.value skips disabled fields; form.getRawValue() includes them. Send getRawValue() when you need every field.
  • Server-side validation still matters: the back must check everything again. Show its field errors with control.setErrors({ server: message }).
  • Custom, async and cross-field validators, and the experimental signal forms: see Forms.

CRUD 2 · The service builds the request

In short

The contacts app above is this card's demo. Watch "What was sent" at its bottom.

The component never builds URLs or bodies: it calls api.create(draft). The service wraps HttpClient, picks the method (GET, POST, PUT, DELETE), the URL, the query params and the body, and types the response. The request still goes through the app's interceptors, which add the auth header and log it.

Vue → Angular

  • An Observable is lazy: calling api.create() sends nothing. The request goes out on subscribe(), and every new subscribe sends it again.
  • post<Contact>() is a type assertion, not a check: if the back sends something else, TypeScript will not notice.
  • HttpClient is registered once in app.config.ts with provideHttpClient(withInterceptors([…])), like an axios instance with its interceptors. See HTTP & RxJS.

CRUD 3 · Handling the response: loading, success, error

In short

The contacts app above is this card's demo. Try a save that works, then one that fails.

The component subscribes with two callbacks. next gets the saved contact: the list is updated with it (a new array) and the form is cleared. error gets an HttpErrorResponse: a message is shown and the form keeps its values. A saving signal disables the buttons in between.

Vue → Angular

  • Updating the list from the response saves a GET. Reloading the whole list after each write is simpler and always right; pick one per screen.
  • HTTP Observables complete after one answer, so there is nothing to unsubscribe. If the user may leave mid-request, add takeUntilDestroyed() to cancel it.
  • Errors shown everywhere (401, network down) belong in an interceptor, once for the whole app. This page skips that global banner because it shows its own message.
  • Prefer async / await? await firstValueFrom(api.create(draft)) works for one-shot requests. Searches and other streams stay Observables.
