Control flow

Blocks that add, repeat, switch and lazy-load parts of a template. They are built into the template syntax (stable since v17), so they need no imports. The code of each demo lives in src/app/topics/02-control-flow/demos/.

Templates are not static: parts of them appear, repeat or wait depending on the data. Angular has built-in blocks for that, written with @. A block decides which DOM exists, not only what is visible: 

 @if       show one block or another     creates and destroys its content
 @for      repeat a block per item       keeps each row by its track key
 @switch   one block among several values
 @defer    load a block, and its code, later

@if, @else if, @else

In short

@if (condition) { ... } renders its block only while the condition is truthy. Chain @else if and a final @else. With @if (expr; as name) the value of expr gets a name inside the block, and TypeScript narrows its type (here User | undefined becomes User).

  • A hidden block is removed from the DOM and its components are destroyed. To only hide something and keep its state, bind [hidden] or a class instead.
  • as is handy with values that may be missing: signals returning T | undefined, or obs$ | async.
  • Gotcha: @if tests truthiness, so 0 and '' count as false. Write value !== undefined when zero is a valid value.

@for and @empty

In short

@for (item of items; track item.id) { ... } repeats a block per item. track is required. @empty renders when the list is empty. The implicit variables $index, $count, $first, $last, $even and $odd are always available; let pos = $index gives one a new name.

  • Rename the implicit variables in nested loops (let row = $index): the inner loop's $index hides the outer one.
  • @for works with any iterable: arrays, Set, Map (items are [key, value] pairs). For plain objects use the keyvalue pipe.
  • Update lists immutably ([...tasks, newTask]). Setting a signal to the same array reference does not notify its readers.

track and DOM reuse

In short

track tells Angular which DOM rows belong to which items. After a change, rows with a known key are kept (and moved if needed); only new keys create rows. Each row here is a component whose #number increases every time one is created. Type something in the inputs, then use the buttons.

  • Reverse: with track fruit.id the rows move along with your text. With track $index the rows stay in place and only the names change, so your text now sits next to another fruit.
  • Reload creates equal but new objects. track fruit.id and track $index keep every row. Tracking by identity recreates all of them and your text is lost. Angular logs the warning NG0956 in the console about it.
  • Track by a unique, stable id from your data. Duplicate keys log NG0955.
  • track $index is fine for static lists that never reorder. With rows that hold state (inputs, child components) it attaches that state to the wrong item.
  • In *ngFor, trackBy was optional and took a function. Without it items were tracked by identity, a classic performance bug; @for makes you choose.

@switch

In short

@switch (expr) renders the first @case whose value is equal (===) to expr, or @default when none matches. There is no fall-through. Consecutive @case blocks share one body, and @default never; makes the type checker report a union member without a case.

  • Try it: add 'student' to the Plan type in switch-demo.ts and the build fails until you add a case for it.
  • Grouped cases and @default never; are recent additions (this project runs Angular 21.2). You will not find them in v19/v20 code, which uses a @default block or repeated bodies instead.
  • The @case value is an expression: @case (Status.Done) works with enums or constants the component exposes.
  • Gotcha: @default never; fails on @switch (plan()). TypeScript cannot narrow the result of a function call, and a signal read is one. Store it first with @let currentPlan = plan(); and switch on that.

@defer

In short

@defer lazy-loads part of a template: the components, directives and pipes used only inside it go into a separate JavaScript chunk, fetched when a trigger fires. @placeholder shows before that, @loading while the chunk downloads, and @error if it fails. Without a trigger, on idle is used.

Other triggers: on hover, on immediate, and prefetch on ... to download early but render later (e.g. @defer (on interaction; prefetch on idle)).

  • A dependency is only deferred if it is standalone and not used anywhere else in the same component (outside @defer in the template, or in a viewChild). Otherwise it stays in the parent's chunk.
  • minimum keeps a block on screen for some time to avoid flicker. @loading (after 100ms) shows the loader only when loading is slow.
  • Once loaded, a block stays loaded: when is a one-way switch, not an @if.
  • Gotcha: with HMR on (the ng serve default) Angular loads every @defer dependency eagerly and logs NG0751. Triggers and placeholders still work, but no chunk is fetched. Run ng serve --no-hmr to watch the heavy-widget chunk arrive in DevTools → Network, or check the lazy chunks listed by npm run build.

Legacy: *ngIf, *ngFor, [ngSwitch]

In short

Before v17, templates used structural directives from @angular/common, imported in each component. The * is shorthand for wrapping the element in an <ng-template>. They still work, are deprecated since v20, and appear in most v19 codebases.

ng generate @angular/core:control-flow migrates a project to the built-in syntax. The Legacy & migration topic covers old-style Angular as a whole.

  • *ngIf ... else needs a separate <ng-template #ref>; @else is inline.
  • Only one structural directive fits on an element. *ngIf plus *ngFor needed an extra <ng-container>. Blocks nest freely.
  • Built-in blocks need no imports and type-check better (e.g. narrowing in @if).
