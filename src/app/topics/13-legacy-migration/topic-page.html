Legacy & migration

Most v19 codebases, and many v20 ones, still look like this: NgModules, decorator inputs and outputs, constructor injection, *ngIf / *ngFor, class guards and zone.js. The first card is a small feature written that way (legacy/, loaded as a lazy NgModule). The other cards put each legacy piece next to its modern equivalent and name the schematic that migrates it.

A feature built the pre-v17 way

TaskBoardComponent reads a BehaviorSubject through the async pipe and passes the tasks to TaskListComponent through @Input(); the list reports clicks with @Output() + EventEmitter. Both are declared in TasksModule, which this standalone page imports. Hover a task to see the @HostBinding directive; press Esc to clear the input (@HostListener).

Code: legacy/tasks.module.ts, task-board.component.*, task-list.component.*, highlight.directive.ts, task.service.ts

  • Old file naming: task-list.component.ts, task.service.ts, tasks.module.ts, and class names ending in Component / Service. Since v20 the CLI generates task-list.ts with class TaskList. Both work; follow whatever the codebase already does.
  • standalone: false is needed on declared components since v19. In code written before v19 there is no standalone flag at all, because false was the default.
  • This project's lint config enforces the modern APIs, so eslint.config.js turns those rules off for legacy/ only.

NgModule → standalone

An NgModule groups declarations and decides what their templates can see. A standalone component lists its own dependencies in imports, so there is one place to look. This topic is still loaded as a module: loadChildren: () => import('./legacy/legacy.module').then((m) => m.LegacyModule), and RouterModule.forChild(routes) registers its child routes.

Code: legacy/legacy.module.ts, topics.registry.ts

  • Both worlds mix: a standalone component imports a module (this page imports TasksModule), and a module imports standalone components.
  • ng generate @angular/core:standalone runs in three passes: convert declarations, remove the empty modules, switch to bootstrapApplication. Run them in that order and build between them.
  • A module that only brings providers (HttpClientModule, StoreModule.forRoot) becomes a provide…() function in app.config.ts. When a library has none yet, wrap its module in importProvidersFrom(...).

@Input / @Output → input() / output()

A decorator input is a plain field that Angular writes to; the component learns about changes in ngOnChanges or through a setter. A signal input is read-only and can feed a computed, so derived state needs no lifecycle hook.

  • Migrations: signal-input-migration and output-migration. They skip inputs that the component writes to itself: those become a model() or a local signal by hand.
  • @Input({ required: true }) → input.required(). @Input({ transform: booleanAttribute }) → input(false, { transform: booleanAttribute }).
  • In templates and specs the binding is the same ([tasks], (toggled)); in TypeScript every read becomes a call: this.tasks → this.tasks().

Constructor injection → inject()

Both styles resolve from the same injector. inject() works in field initializers, so values derived from a service move out of the constructor, and subclasses no longer repeat the parent's dependencies in super(...).

  • Migration: ng generate @angular/core:inject. Parameter decorators become options: @Optional() → { optional: true }, @Self() → { self: true }.
  • inject() only works in an injection context: field initializers, the constructor, factories, guards and resolvers. Not in ngOnInit or a click handler.

*ngIf / *ngFor / [ngSwitch] → @if / @for / @switch

Structural directives needed CommonModule (or NgIf, NgFor…) in the imports, an <ng-template> for the else branch and a trackBy function. The built-in blocks need no imports and make track mandatory.

Topic 02 has a live side-by-side of both syntaxes.

  • Migration: ng generate @angular/core:control-flow. The directives are deprecated since v20.
  • *ngIf="tasks$ | async as tasks" hides the content while the value is falsy, so an empty string or 0 renders nothing. @if behaves the same way.

@ViewChild, @HostListener → viewChild(), host

A decorator query is undefined until ngAfterViewInit, hence the !. A signal query is a signal: read it anywhere, and computed or effect react when the element appears. Host bindings and listeners move to the host object in the decorator.

  • Migration: ng generate @angular/core:signal-queries-migration.
  • There is no schematic for @HostBinding / @HostListener; move them to host: {} by hand. Both still work and are not deprecated, but the style guide prefers host.

  • Class guards and resolvers are deprecated (v15.2). There is no schematic: rewrite them by hand, or wrap them with mapToCanActivate / mapToResolve first.
  • The same applies to CanLoad, replaced by canMatch, which also runs before a lazy route is loaded.

zone.js → zoneless

Both buttons write status = 'saved' in a setTimeout. With zone.js, Angular ran change detection after every async callback, so both worked. This app is zoneless (the default since v21): the first button stays on "saving…" until something else refreshes the component, while the second calls markForCheck().

Code: legacy/save-status.component.ts; topic 06 covers change detection

  • Legacy code that already uses OnPush with the async pipe or signals usually works zoneless as is. The code that breaks writes plain fields in callbacks (setTimeout, subscribe, third-party libraries).
  • v20 opted in with provideZonelessChangeDetection(). A v21 app that still needs zone.js adds provideZoneChangeDetection() and loads zone.js in the polyfills.

Running the migrations

{{ commands }}

ng update moves one major version at a time and runs the required migrations of that version automatically. The migrations to modern APIs are optional: run them with ng generate, one per commit, and read the diff. Each one prints what it could not convert and why.

  • The schematics also update the specs. Run the tests after each one; the build alone does not catch everything (for example a field that is now a signal but is still read without () in a string template).
  • ng generate @angular/core:signals runs the input, output and query migrations together.
