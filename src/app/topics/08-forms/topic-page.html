Forms

Angular has three ways to build forms. Template-driven forms declare the controls in the template with ngModel. Reactive forms build a typed model of controls in the class and bind the template to it. Signal forms (new, experimental in v21) derive the whole form from a signal. All the demos use the same CSS for the state classes Angular adds to controls. The code of each demo lives in src/app/topics/08-forms/demos/.

Every form control tracks the same things, whatever API you use: its value, whether it is valid (its rules pass), dirty (the user changed it) and touched (the user left it). Error messages usually depend on all three. Angular has three ways to build forms; they differ in where that model lives: 

 template-driven   the template declares it    ngModel + required, minlength…
 reactive          the class builds it         FormGroup, FormControl, FormArray
 signal forms      a signal is the model       form(signal, schema)  (experimental)

Template-driven suits small forms; reactive is what most existing apps use; signal forms are the future but still experimental.

Template-driven forms: ngModel

In short

FormsModule gives every <form> an NgForm and every input with ngModel and a name a control inside it. Validation comes from HTML attributes (required, minlength, email), which are Angular validator directives. #nameCtrl="ngModel" exports the control to read its state. Type, leave the field, then press Reset: the border colour comes from the ng-invalid / ng-touched / ng-dirty classes.

  • Each ngModel inside a form needs a name: it is the key in f.value. Without it Angular throws.
  • touched = the field lost focus once; dirty = the user changed the value. Show errors on touched (or after submit), not while the form is empty.
  • (ngSubmit) instead of (submit): it also sets f.submitted. resetForm() clears values and states and submitted.
  • Template-driven vs reactive: template-driven is quick for small, static forms (login, search). Choose reactive for dynamic fields, cross-field rules, complex validation or when you want to unit test the form without a template. Most company codebases use reactive.
  • Vue comparison: [(ngModel)] ≈ v-model, but Angular also tracks validity and touched/dirty per field.

Typed reactive forms

In short

The class builds a FormGroup with NonNullableFormBuilder; the template binds to it with [formGroup], formControlName and formGroupName. The types are inferred from the initial values, so form.controls.age.value is a number. Compare the buttons: setValue needs every field (try "name only"), patchValue takes any subset. Disable the age and compare form.value with getRawValue().

  • Why typed forms matter (v14+): setValue({ nme: 'x' }) or controls.nmae fail at compile time, and value is typed. Old code with UntypedFormGroup or any loses all of that.
  • FormBuilder makes FormControl<T | null>, because reset() sets null. NonNullableFormBuilder (or fb.nonNullable) makes FormControl<T> and resets to the initial value.
  • form.value is Partial<…> because disabled controls are left out. getRawValue() includes them and is fully typed.
  • valueChanges / statusChanges are Observables that fire on user input and on setValue, patchValue and reset (pass { emitEvent: false } to stay silent). Forms are not signals yet: this demo wraps them with toSignal() so the zoneless view refreshes after changes made from code.

FormArray: a dynamic list

In short

A FormArray holds a list of controls (or groups) whose length changes at runtime: push() adds one, removeAt(i) removes one. In the template, formArrayName scopes the list and each input binds by index with [formControlName]="i". Remove every skill to see the array validator.

  • In @for, track the control object, not $index. With $index, removing the first item reuses its input for the second control, and the focus jumps to the wrong field.
  • Validators can go on the array itself and count its items. Gotcha: for "at least one" use Validators.required; minLength(1) skips empty values, and an empty array counts as empty. Each item keeps its own validators.
  • For a list of objects, push fb.group({ … }) items and use [formGroupName]="i" in the loop.
  • FormRecord is the variant for keys unknown at compile time (a map instead of a list).

Validators: custom, async and cross-field

In short

forbiddenValue('admin') is a custom sync validator: a function of the control that returns null or an errors object. usernameAvailable() is async: it returns an Observable after a fake 600 ms server call, and the control is PENDING meanwhile (try "angular"). fieldsMatch sits on the passwords group, the only place that sees both fields.

  • Validators are plain functions (ValidatorFn). A factory function lets them take parameters, like the built-in Validators.minLength(3).
  • Async validators only run when all sync validators pass, and each new value cancels the running check. For a server call, add { updateOn: 'blur' } to the control or a debounce so you do not call the API on every keystroke.
  • A cross-field error lives on the group: read it with passwords.hasError('fieldsMismatch'), not on the confirm control. The confirm input stays ng-valid.
  • While a check is running, the form is PENDING: neither valid nor invalid. Handle that state on submit.

Signal forms (experimental)

In short

form(model, schema) from @angular/forms/signals builds a field tree from a WritableSignal. The schema function declares rules per path (required, email, minLength, validate). [formField] binds an input to a field, and every piece of state is a signal: loginForm.email().errors(), loginForm().valid(). Typing updates model() and "model.set(example)" updates the inputs.

  • Signal forms are experimental: the API may change in minor versions and it is not what current job codebases use. Learn reactive forms first.
  • No FormControl objects, no valueChanges, no setValue: the model signal is the single source of truth.
  • Rules are reactive: valueOf(path.password) in the confirm rule makes it re-run when the password changes. Other rules: disabled, hidden, readonly, validateAsync.
  • submit(form, action) marks every field as touched and runs the action only when the form is valid.
