Routing

The router maps URLs to components. This topic is lazy-loaded with loadChildren: its child routes live in 07-routing.routes.ts and render in the mini app below, which has its own nested <router-outlet>. The links in the other cards drive the same mini app, and the real browser URL changes with it. The code of each demo lives in src/app/topics/07-routing/demos/.

Child routes and a nested outlet

The app shell has the top-level <router-outlet>, which renders this page. This page's route has children, and they render in the second outlet, inside the mini app. Type a path in the address bar (for example /products/3) and press Go, or use the nav. routerLinkActive highlights the link that matches the URL: "Products" stays active on /products/3 because it matches by prefix.

Code: 07-routing.routes.ts, mini-app.ts|html, views/*.ts

  • loadComponent lazy-loads one component; loadChildren lazy-loads a whole Routes array. Both become a separate chunk, fetched on the first visit.
  • Preloading fetches lazy chunks in the background after the app starts: provideRouter(routes, withPreloading(PreloadAllModules)). Without it (the default, used here) a chunk loads on first click. A custom PreloadingStrategy can preload only routes flagged in data.
  • { exact: true } in [routerLinkActiveOptions] stops the prefix match; the sidebar uses it for Home, otherwise / would always be active. ariaCurrentWhenActive="page" adds aria-current for screen readers.
  • A route can declare providers: this topic's FakeAuth lives in the route's environment injector, shared by its children and guards. It is not destroyed when you leave the route.
  • A route with children but no component (products here) just groups URLs. Its children render in the nearest outlet above.

Route params and query params as inputs

Try in the mini app: products/2 · products?sort=price · products?sort=name

withComponentInputBinding() (in app.config.ts) makes the router set component inputs whose names match a route param (:id), a query param (?sort=), a data key or a resolve key. The detail view declares id = input.required({ transform: numberAttribute }); the list declares sort = input<string>().

Code: views/product-list.ts, views/product-detail.ts

  • Params are always strings. Convert them with a transform (numberAttribute) or a computed().
  • Moving from /products/1 to /products/2 reuses the same component: only the inputs change. Code that read the id once in ngOnInit (the old route.snapshot.paramMap pattern) shows stale data; inputs and computed() do not.
  • When a query param disappears from the URL, its input is set to undefined. Give inputs a default or handle undefined.
  • Without input binding: inject(ActivatedRoute).paramMap / queryParamMap are Observables (wrap them with toSignal()).
  • By default a child only sees its parent's params when the parent has an empty path or no component. withRouterConfig({ paramsInheritanceStrategy: 'always' }) passes them all down.

Functional guards: canActivate and canDeactivate

Try in the mini app: admin (while logged out) · edit, change the name, then click "Products"

authGuard is a CanActivateFn: logged out, it returns a UrlTree to login?returnUrl=…, which cancels the navigation and starts a new one. After logging in, the login view navigates back to returnUrl. unsavedChangesGuard is a CanDeactivateFn that asks the component being left; it returns a promise that the "Leave" / "Stay" buttons resolve.

Code: guards.ts, views/login-view.ts, views/edit-view.ts

  • Guards are plain functions that run in an injection context, so they call inject(). Class guards (implements CanActivate) still work, but functions are the recommended style.
  • A guard returns boolean, UrlTree or RedirectCommand, directly or as a Promise / Observable. Return a UrlTree to redirect; calling router.navigate() inside the guard and returning false works but races with the current navigation.
  • Other guards: canActivateChild (every child of a route), canMatch (if false, the router tries the next route with the same path; also stops a lazy chunk from being fetched).
  • Guards are UX, not security: the real check belongs on the server. Also, canDeactivate does not run when the tab closes or reloads; use a beforeunload listener for that.

Resolvers and route titles

Try in the mini app: products/3 · products/99 (does not exist). Watch the browser tab title.

productResolver is a ResolveFn: the router waits for it (400 ms of fake delay, shown as "Navigating…") before it activates the detail view, which gets the result as its product input. For an unknown id it returns a RedirectCommand to the list. Each route has a title; the product route uses a title resolver to show the product name.

Code: product-resolvers.ts

  • The old page stays on screen until the resolver finishes, so show progress: router.currentNavigation() is a signal (since v20.2) that is not null while a navigation runs.
  • Resolvers delay navigation. For slow data it often feels better to navigate at once and load inside the component (resource(), httpResource()) with a loading state.
  • inject() in an async resolver or guard only works before the first await.
  • The deepest route with a title wins. Provide a custom TitleStrategy to add a suffix everywhere instead of repeating it.

Redirects and wildcard routes

Try in the mini app: the topic root · catalog/4 (old URL) · does-not-exist

The empty child path redirects to products. catalog/:id redirects with a function that builds the new path from the params. The topic has its own ** route, so an unknown path under /topics/07-routing shows the "Nothing here" view instead of the app-wide 404 page.

Code: 07-routing.routes.ts

  • A redirect from '' needs pathMatch: 'full': with the default 'prefix', the empty path matches every URL.
  • Routes match in order, first match wins. Keep ** last; the app-level one in app.routes.ts is guarded by a unit test.
  • redirectTo paths starting with / are absolute; others are relative to the parent route. Since v20 a redirect function may also return a Promise or an Observable.
  • Redirects run before guards, and a route with redirectTo cannot have a component or children.

Programmatic navigation

Router.navigate() takes an array of commands, relative to a route when you pass relativeTo. Router.navigateByUrl() takes a full URL string. Both return a promise: true when the navigation finished, false when a guard said no. Open "Edit profile", change the name, press a button here and choose "Stay": false. A redirect is different: "navigateByUrl('…/admin')" while logged out resolves to true, the result of the navigation to the login page.

Code: programmatic-nav-demo.ts, views/product-detail.ts (Previous / Next), views/login-view.ts

  • Prefer routerLink for anything the user clicks: it renders a real <a href> (open in a new tab, copy link). Navigate from code after an action, like saving a form or logging in.
  • Without relativeTo, navigate() resolves from the root. Inside a component, inject(ActivatedRoute) gives the route to navigate relative to.
  • Options: queryParams, queryParamsHandling: 'merge' | 'preserve', fragment, replaceUrl (no new history entry), state (data that does not go in the URL).
  • Vue Router comparison: router.push() ≈ navigateByUrl(); beforeEnter / beforeRouteLeave ≈ canActivate / canDeactivate; props: true ≈ input binding.
