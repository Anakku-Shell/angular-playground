Components & templates

A component is a TypeScript class plus a template. These demos cover the template syntax that connects the two. The code of each demo lives in src/app/topics/01-components-templates/demos/.

Interpolation

{{ expression }} renders the result of a TypeScript-like expression as text. It can read class members (signals are called: user().name), do arithmetic, use ternaries, ?. and ??.

Code: interpolation-demo.ts / .html

  • Keep templates light: move non-trivial logic into a computed() in the class (like total). It is cached and only recomputed when its signals change.
  • Interpolation always escapes HTML. To render markup, bind [innerHTML]; Angular sanitizes it and strips anything dangerous.
  • Templates only see the component's members: no window, console or globals. Expose what you need from the class.

Property, attribute, class and style bindings

[prop]="expr" sets a DOM property ([disabled], [value]). Things that only exist as HTML attributes, like aria-* or colspan, need [attr.name]. [class.name] toggles one class and [class] takes a string, array or map. [style.prop] sets one style, with an optional unit: [style.width.px].

Code: bindings-demo.ts / .html

  • Inspect the button in DevTools: aria-pressed appears as an attribute, while disabled is a property (the attribute is added by the browser).
  • [attr.x]="null" removes the attribute. With false it is set to the text "false".
  • Static class="...", [class] and [class.x] merge; they do not overwrite each other.

Event binding

(event)="statement" runs a statement when the DOM event fires. $event is the native event object (MouseEvent, KeyboardEvent...). Key events accept filters: (keyup.enter), (keyup.escape), (keydown.shift.tab).

Code: events-demo.ts / .html

  • For (input), $event is a plain Event: cast its target (event.target as HTMLInputElement) in the class, not in the template.
  • Prefer calling a method (add()) over long statements in the template: it is easier to read and to test.
  • An event handled by a template listener also schedules a re-render of the component.

Two-way binding with ngModel

[(ngModel)]="name" ("banana in a box") is shorthand for a property binding plus an event binding: [ngModel]="name()" (ngModelChange)="name.set($event)". Both inputs above share the same signal. ngModel comes from FormsModule; forms get their own topic.

Code: two-way-demo.ts / .html

  • [(x)] works with any component that has an input x and an output xChange. The model() API creates that pair (see Component communication).
  • With a signal, write [(ngModel)]="name" (no parentheses): Angular needs the signal itself to call set() on it.

Template reference variables

#name on an element creates a template variable pointing to that DOM element (or to the component instance, when placed on a component). It can be used anywhere in the same template, for example to pass a value to a method: greet(nameInput.value).

Code: template-refs-demo.ts / .html

  • Type in the input and watch nameInput.value: it does not update. Nothing tells Angular to re-render, because typing triggers no bound event. Click a button and it catches up. Keep state in signals, not in DOM elements.
  • #ref="exportName" points to a directive instead (e.g. #m="ngModel"). It shows up in the Forms topic.

@let

@let name = expression; declares a read-only variable in the template. Its value is kept up to date when the expression's inputs change. A common use is subscribing once with @let customer = customer$ | async; and reusing the value.

Code: let-demo.ts / .html

  • Stable since Angular 19 (developer preview in 18.1). Not available in older codebases.
  • A @let is visible in its block and nested blocks, only after its declaration. It cannot be reassigned from the template.
  • If the value belongs to the component's logic (not just the view), use a computed() in the class instead.

Built-in pipes

A pipe transforms a value for display: value | pipe: arg1 : arg2. Pipes chain left to right (clock$ | async | date: 'HH:mm:ss'). They come from @angular/common and are imported per component, like components are.

Code: pipes-demo.ts / .html

  • date and currency format with the app's locale (en-US by default). Other locales need registerLocaleData and LOCALE_ID.
  • async subscribes to an Observable or Promise and unsubscribes when the component is destroyed: no manual cleanup.
  • Most pipes are pure: they only re-run when the input value (or object reference) changes. async, json and keyvalue are impure and re-run on every check.
  • json is a debugging aid: handy while developing, rarely shipped.

Component styles and ViewEncapsulation

Component styles are scoped by default. encapsulation controls how: Emulated (default) adds unique attributes to the component's elements and rules; None adds the styles globally; ShadowDom uses the browser's native shadow DOM. :host targets the component's own element.

Tick the checkbox: the None component's .enc-sample rule underlines every element with that class, in the parent and in the other samples. Untick it and the rule is gone: Angular removes a component's styles when its last instance is destroyed. The ShadowDom button ignores the page's global button style, because styles.scss cannot enter a shadow root.

Code: encapsulation-demo.ts, encapsulation/*.ts

  • Stay with Emulated. None is for deliberate global styles (e.g. theming a third-party widget) and needs unique class names.
  • Emulated styles do not reach projected content or child components. ::ng-deep pierces that but is deprecated; prefer global styles or CSS custom properties.
  • CSS custom properties (var(--x)) cross every boundary, shadow DOM included: the standard way to theme components.
  • Gotcha: ShadowDom does not fully isolate an Angular component. Angular copies the styles of its other components into every shadow root, so a None rule still reaches in.
