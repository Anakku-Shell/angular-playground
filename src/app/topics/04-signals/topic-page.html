Signals & reactivity

A signal is a value that tells its readers when it changes. Templates, computed() and effect() track the signals they read, and only those parts update. With OnPush and zoneless change detection (this app's setup), a signal change refreshes only the components that read it. The code of each demo lives in src/app/topics/04-signals/demos/.

signal() and computed()

quantity = signal(1) creates a writable signal: read it with quantity(), change it with set(value) or update(fn). total = computed(() => ...) is a read-only signal derived from others. It is lazy (it runs only when something reads it) and memoized (it reruns only after a dependency changed). Change the quantity while the total is hidden, then show it, hide it and show it again, and watch the run number.

Code: basics-demo.ts / .html

  • Dependencies are found at run time: the signals a computation actually read on its last run. A signal read only inside a branch that did not run is not a dependency until it does.
  • Signals hold values, so use immutable updates for objects and arrays: items.update((list) => [...list, item]). Mutating the array in place keeps the same reference, and readers are not notified.
  • A computed() must be a pure function of its dependencies: writing signals inside it throws an error.
  • Signals + OnPush = fine-grained updates: a signal read by a template marks only that component for refresh, not the whole tree.
  • Vue: signal ≈ ref (read with count(), not .value), computed ≈ computed.

Equality functions

A signal notifies its readers only when the new value is different from the current one. By default "different" means !Object.is(a, b), so a new object with the same fields is a change. The option signal(point, { equal: samePoint }) replaces that comparison: here an equal copy is ignored, and the computed that depends on it does not rerun.

Code: equality-demo.ts / .html

  • computed() and linkedSignal() accept equal too: a derived value that did not change stops the update from reaching its own readers.
  • Mutating an object in place and calling set() with the same reference is ignored by the default equality. Create a new object instead.
  • Keep equality functions cheap: they run on every set(). Deep comparisons of large structures cost more than the update they save.

untracked(): reading without depending

Inside a computation, untracked(b) (or untracked(() => b())) reads the current value of b without making it a dependency. Press "b + 1": the first sum updates, the second does not. Press "a + 1": the second sum reruns and picks up the latest b.

Code: untracked-demo.ts / .html

  • Its main use is in effect(): react to one signal and read others as context, e.g. log a page view with the current user, without logging again when the user changes.
  • Also wrap calls into code you do not control (a service method, a third-party library) inside an effect: any signal they read would otherwise become a dependency too.

effect(): syncing with the outside world

effect(() => ...) runs a function now and again whenever the signals it read change. It is for side effects outside Angular's data flow: storage, logging, a canvas, a third-party widget. This one saves the draft to localStorage half a second after the last keystroke. The onCleanup callback cancels the pending save when the draft changes again, so typing quickly produces a single save.

Code: effect-demo.ts / .html

  • Do not use an effect to copy one signal into another (effect(() => this.total.set(this.a() + this.b()))). Derive it instead: computed(), or linkedSignal() when it must also be writable. Effects that write signals cause extra change detection passes and are hard to follow.
  • Effects run asynchronously, during change detection, not synchronously on set(). Several changes in a row produce one run.
  • effect() needs an injection context (constructor or field initializer), or { injector }. A component's effects are destroyed with it; the returned EffectRef has destroy() for earlier cleanup.
  • For DOM work after rendering use afterRenderEffect() or afterNextRender() (Lifecycle topic).
  • Vue: effect ≈ watchEffect. There is no watch(source, cb): read the source in the effect and wrap the rest in untracked().

linkedSignal(): writable derived state

The shipping method depends on the country but the user can also pick one. A linkedSignal is a writable signal that is recomputed whenever its source changes. The long form linkedSignal({ source, computation: (methods, previous) => ... }) also receives the previous value: pick "Express", switch to Portugal and it is kept; switch to Andorra and it falls back to "Standard".

Code: linked-demo.ts / .html

  • The short form linkedSignal(() => this.methods()[0]) always resets to the first option (see the Component communication topic).
  • A set() lasts until the source changes. Then the computation runs again and decides.
  • Stable since v20. Without it, the usual pattern was an effect() that writes a signal, which is the pattern the effect demo warns about.

resource(): async data as signals

resource({ params, loader }) runs an async loader (a Promise) whenever params() changes, and exposes the result as signals: value(), status(), isLoading(), error() and hasValue(). A new request aborts the previous one through the abortSignal passed to the loader: click several ids quickly and watch the cancelled count. User 4 does not exist, to show the error state.

Code: resource-demo.ts / .html

  • Experimental in v21: the API may still change. Stable alternatives are a service with an HttpClient Observable plus toSignal().
  • Variants: rxResource (loader returns an Observable, from @angular/core/rxjs-interop) and httpResource (an HTTP GET driven by signals, from @angular/common/http; HTTP topic). Both experimental.
  • value() throws while the resource is in the error state: check error() or hasValue() first, as this template does.
  • reload() runs the loader again with the same params. If params() returns undefined, the resource goes idle and the loader does not run.

RxJS interop: toSignal() and toObservable()

toObservable(this.query) turns a signal into an Observable, so RxJS operators such as debounceTime can process it. toSignal(observable$, { initialValue }) turns the result back into a signal the template can read. Type in the box: the raw query changes on every key, the debounced one 300 ms after you stop. The seconds counter is toSignal(interval(1000)).

Code: interop-demo.ts / .html

  • toSignal subscribes immediately and unsubscribes when the component (its injection context) is destroyed: no async pipe, no manual unsubscribe.
  • Without initialValue the signal is T | undefined until the first emission. Use { requireSync: true } for Observables that emit synchronously (like a BehaviorSubject).
  • toObservable emits asynchronously, once per change detection pass: several set() calls in a row emit only the last value.
  • Use signals for state the template shows; keep RxJS for events over time (debounce, cancellation, combining streams). Stable since v20.

outputFromObservable(): an Observable as an output

The hold button builds a stream with RxJS: each press starts an 800 ms timer and a release cancels it (switchMap + takeUntil). held = outputFromObservable(stream$) exposes that stream as a regular output, so the parent listens with (held)="onHeld($event)". Press and hold, then try a quick click. Keyboard: hold Space or Enter.

Code: output-observable-demo.ts, interop/hold-button.ts

  • The opposite direction, outputToObservable(child.held), turns an output into an Observable.
  • Unsubscribing is automatic when the component is destroyed. For other subscriptions use takeUntilDestroyed() in an injection context.
  • Legacy: an @Output() was an EventEmitter (a Subject), so components often exposed Observables as outputs directly.
